# TaskFlow Manager — MERN Stack Assessment Project

A responsive single-page Task & Project Manager built to match the supplied MERN Stack Technical Assessment. It implements Create, Read, Update, Delete, status toggle, search, status filters, validation, MongoDB persistence, and automated tests.

## Stack
- React 18 + Vite, custom responsive CSS, Lucide icons
- Node.js + Express REST API
- MongoDB + Mongoose
- Vitest, React Testing Library, Supertest-ready API structure
- Clean Architecture separation: domain, application, infrastructure, presentation

## Requirements
- Node.js 18.18+ (Node 20 LTS recommended)
- MongoDB Atlas database or local MongoDB

## Run locally
1. Create a MongoDB database (Atlas free tier works).
2. Copy `server/.env.example` to `server/.env` and set `MONGODB_URI`.
3. Install dependencies:
   ```bash
   npm install --prefix server
   npm install --prefix client
   ```
4. Start both apps in separate terminals:
   ```bash
   npm run dev --prefix server
   npm run dev --prefix client
   ```
5. Open http://localhost:5173. The Vite dev server proxies no requests; set `VITE_API_URL=http://localhost:5000` in `client/.env` if needed. The default API base is same-origin, so for local development create `client/.env` with `VITE_API_URL=http://localhost:5000`.

## Tests
Run all tests:
```bash
npm test
```
Or individually:
```bash
npm test --prefix server
npm test --prefix client
```
The suite covers required-title validation, valid task creation normalization, invalid priority rejection, task stats, and form submission/validation.

## Production build
```bash
npm run build --prefix client
```
The Express server serves the generated `client/dist` files as well as `/api` endpoints. Set `MONGODB_URI` in the hosting provider's environment variables and start with `npm start --prefix server` (or `node server/src/index.js` from the repository root).

## Deploy (Render + MongoDB Atlas)
This repository includes `render.yaml` for a single Render web service:
1. Push the project folder to a new GitHub repository.
2. Create a free MongoDB Atlas cluster. Create a database user and allow the Render service to connect (Atlas Network Access: allow `0.0.0.0/0` for this assessment, or configure a restricted IP strategy).
3. In Render, choose **New → Blueprint** and connect the GitHub repository. Render reads `render.yaml`.
4. In the Render service Environment settings, add `MONGODB_URI` with your Atlas connection string. Keep credentials private.
5. Wait for deploy. Open the generated `https://...onrender.com` URL and test create/edit/toggle/delete and refresh persistence.

The live deployment cannot be published from this workspace because it requires your own GitHub, MongoDB Atlas, and hosting accounts/credentials. The project is preconfigured for this deployment flow; the live URL is generated by Render after you connect those accounts.

## API endpoints
| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Health check |
| GET | `/api/tasks?search=&status=All` | List/search/filter |
| POST | `/api/tasks` | Create |
| PUT | `/api/tasks/:id` | Update |
| PATCH | `/api/tasks/:id/toggle` | Toggle Pending/Completed |
| DELETE | `/api/tasks/:id` | Delete |

## Architecture
```text
server/src/
  domain/          Task validation and normalization rules
  application/     Task use cases / CRUD service
  infrastructure/  Mongoose Task model
  presentation/    Express routes and HTTP app
client/src/
  application/     UI helper/business calculations
  infrastructure/  API client
  presentation/    React page and reusable components
  __tests__/       UI and helper tests
```

## Assessment walkthrough (5 minutes)
1. Create a task with title, description, priority and due date.
2. Search by title and switch All/Pending/Completed filters.
3. Edit a task, toggle its completion state, then delete it (confirm prompt).
4. Refresh the page to demonstrate MongoDB persistence.
5. Run `npm test` and explain the domain validation, CRUD service, API routes and React form tests.

**Important:** The assessment asks candidates to explain every folder, function and test in their own words. Use this project as a learning base and make sure you understand the code before your review.
